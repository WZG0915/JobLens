## 阶段 0

- 当前功能：项目初始化
- 结论：先用标准库验证目录和模拟数据，再引入大模型依赖，可以减少环境问题和业务问题互相干扰。

### Windows 中文输出问题

- 问题：`conda run -n ai_env python app.py` 转发中文输出时出现 `UnicodeEncodeError: gbk`。
- 原因：Conda 父进程使用的控制台编码与子进程输出编码不一致；项目的 3 个测试本身均通过。
- 解决方法：激活 `ai_env` 后运行 `python app.py`，或直接调用 `E:\Anaconda3\envs\ai_env\python.exe`。
- 如何验证：直接使用该解释器运行程序和测试，均成功完成。

## 阶段 1

- 当前功能：简历和岗位 JD 结构化解析
- 设计：用 Pydantic 统一约束 local 与 openai 两种解析模式的输出。
- 设计：自然语言抽取与证据匹配分离；匹配暂时保持确定性，便于复现和测试。
- 安全：只有显式传入 `--provider openai` 才调用外部 API，且请求设置 `store=False`。
- 验证：本地模式覆盖五份岗位，非法结构化数据会转成可读错误。

### 富结构解析与兼容层

- 问题：CLI、README 和测试已经引用阶段 1 流程，但解析、匹配与流水线源文件缺失；项目中同时存在轻量报告模型和完整解析模型。
- 原因：结构升级尚未完成，解析层与报告层之间没有明确边界。
- 解决方法：补齐读取、解析、验证、匹配和流水线；用 `joblens.schemas` 表示可追溯的富结构结果，用 `joblens.models` 保持阶段 1 报告兼容，并在 `extractors.py` 中适配。
- 如何验证：17 个离线测试全部通过；五份模拟 JD、独立简历解析、独立 JD 解析和匹配报告 CLI 均可运行。
