1. 项目目标

先做一个很小但能运行的版本；遇到缺少的知识时，只学习当前功能所需的最小部分。

JobLens 接收用户简历、实习岗位 JD，以及用户的项目与学习资料，生成有证据的岗位匹配分析、能力差距、学习计划和面试问题，并管理岗位投递状态。

对用户有用

可以直接辅助本人筛选岗位和准备面试。

对学习有用

循序学习结构化输出、工具调用、RAG 与 Agent 编排。

对求职有用

有明确场景、工程结构、测试指标和可展示结果。

2. 最终产品能力

  1. 提取岗位要求。
  2. 提取个人能力和项目证据。
  3. 逐项匹配岗位要求。
  4. 区分“匹配、部分匹配、缺少证据、不匹配”。
  5. 给出能力差距和可执行的学习计划。
  6. 生成针对性的面试问题。
  7. 保存岗位和投递状态。
  8. 从学习资料中检索相关内容，并标注来源。
  9. 记录 Agent 调用了哪些工具。
  10. 通过固定评测集验证效果。

3. 项目边界与安全规则

不能编造经历

所有能力判断必须引用简历或项目中的原始证据。

证据不足就说明

没有找到相关经历时输出“缺少证据”，不能自动脑补。

不自动投递

第一版只提供分析、记录和准备，不对外发送简历。

保护个人信息

公开仓库只放虚构简历；真实简历、API Key 与投递记录不提交。

4. 分阶段开发路线

阶段 0

准备环境和模拟数据

预计：1 天

要完成的内容

  • 安装 Python，创建虚拟环境并初始化 Git。
  • 准备一份虚构简历和 5 份模拟岗位 JD。
  • 用 .env 保存 API Key，并配置 .gitignore。
  • 创建源码、测试、数据和文档目录。

只需学习

Python 虚拟环境、依赖、Git 仓库和环境变量分别解决什么问题。

验收标准

  • 程序能读取模拟简历与岗位文件。
  • API Key 不会进入 Git 记录。
  • 项目可以通过一条命令启动。
阶段 1

完成非 Agent 的岗位分析器

预计：3–5 天

先用固定流程验证核心功能：读取简历、解析 JD、匹配证据并生成报告。此时还不使用 LangGraph。

核心函数

  • parse_resume()：提取技能、项目和证据。
  • parse_job_description()：提取岗位要求和重要程度。
  • match_requirements()：完成逐项匹配。
  • generate_report()：输出结构化报告。

需要学习

大模型 API、System/User Prompt、JSON、Pydantic、类型标注与基础异常处理。

Pydantic 的简单理解：它像一张数据表格模板，负责检查大模型有没有按要求填写。

验收标准

  • 能够分析一份简历和一份 JD。
  • 输出固定 JSON 结构，非法输出不会让程序直接崩溃。
  • 每项匹配结论包含证据；没有证据时输出 insufficient_evidence。
阶段 2

改造成工具调用 Agent

预计：4–6 天

将已有 Python 函数变成模型可调用的工具。Agent 根据用户任务选择所需工具，而不是每次执行所有步骤。

第一批工具

  • read_resume
  • read_job_description
  • extract_requirements
  • find_resume_evidence
  • generate_interview_questions
  • save_analysis_report
用户问题 → 模型决定是否调用工具 → 程序执行工具 ↑ ↓ └──────── 工具结果返回模型 ←───────┘ 模型没有新的工具调用时，输出最终答案

必须添加的限制

  • 单次最多调用 8 次工具，避免无限循环。
  • 禁止读取项目范围外的文件。
  • 工具失败时返回结构化错误。
  • 记录每一次工具调用、耗时和结果状态。

验收标准

  • 不同问题会触发不同工具组合。
  • 工具失败时 Agent 能解释，而不是捏造结果。
  • 能够查看完整工具调用记录。
阶段 3

增加岗位管理和持久记忆

预计：3–5 天

使用 SQLite 保存岗位名称、公司、JD、匹配结果、投递状态及时间信息。

新增工具

save_job、list_jobs、get_job、compare_jobs、update_application_status

只需学习

数据库表、唯一 ID，以及 CREATE TABLE、SELECT、INSERT、UPDATE。

验收标准

  • 关闭程序后岗位数据不会丢失。
  • 可以保存、查询、比较岗位和修改投递状态。
  • 不会重复保存完全相同的岗位。
阶段 4

增加学习资料 RAG

预计：5–7 天

RAG 用于检索 Python、RAG、LangGraph、面试题和项目说明等学习资料。短简历直接放入上下文，不需要强行使用 RAG。

文档 → 切分成小段 → Embedding → 保存索引 ↓ 用户提问 → 生成检索问题 → 找到 Top-K 片段 → 带来源回答

第一版范围

  • 支持 Markdown/TXT 文档加载。
  • 完成简单文本切分、Embedding、相似度检索和 Top 3 返回。
  • 回答中显示来源文件。
暂时不要加入：知识图谱、多路召回、reranker、多模态 RAG 和分布式向量数据库。

验收标准

  • 能够导入至少 20 篇学习资料。
  • 回答能引用实际检索到的文件和片段。
  • 找不到资料时明确说明，不伪造引用。
阶段 5

引入 LangGraph

预计：4–6 天

在理解手写 Agent 循环后，再用 LangGraph 组织意图识别、工具执行、证据检查、追问和最终回答。

接收请求 → 识别意图 ─┬─ 岗位匹配 ─┐ ├─ 岗位管理 ─┤ ├─ 学习规划 ─┼─► 执行工具 → 证据检查 ─┬─ 充分 → 结果 └─ 面试准备 ─┘ └─ 不足 → 追问

需要学习

State、Node、Edge、Conditional Edge、Checkpointer 和 Human-in-the-loop。

验收标准

  • 四类任务可以走不同路线。
  • 证据不足时主动追问。
  • 运行中断后可以恢复，并能展示节点轨迹。
阶段 6

建立评测系统

预计：4–6 天

准备 5 份虚构简历、20 份岗位 JD 和人工标注的正确匹配结果。

建议指标

  • 岗位技能提取准确率。
  • 简历证据匹配准确率。
  • 无证据乱判断比例。
  • 工具选择正确率和工具调用成功率。
  • 任务完成率、平均工具调用次数、响应时间与调用成本。

验收标准

  • pytest 可以一键运行。
  • 至少 20 个固定测试案例。
  • 评测结果保存为 JSON 或 Markdown。
  • 修改 Prompt 后可以比较新旧版本结果。
阶段 7

界面、部署与作品集

预计：5–7 天

最后再做界面。新手优先使用 Streamlit 或 Gradio；后续再考虑 FastAPI + React。

最终页面

  • 简历上传和岗位 JD 输入。
  • 匹配结果、证据表格与能力差距。
  • 学习计划、面试问题和岗位管理。
  • Agent 执行轨迹与评测结果。

工程化交付

Docker、日志、.env.example、README、GitHub Actions、架构图、模拟数据和 2 分钟演示视频。

5. 推荐学习顺序

不要按课程目录学习，而要按项目当前需求学习。

顺序知识学到什么程度即可
1Python 环境能安装依赖和运行项目
2大模型 API能发送消息并获取结果
3Prompt能约束任务、格式和规则
4Pydantic能定义和验证结构化输出
5工具调用模型能选择并调用 Python 函数
6Agent 循环能多轮执行工具直到完成任务
7pytest能测试普通函数和工具
8SQLite能保存和查询岗位
9RAG能切分、检索和引用文档
10LangGraph能组织状态、节点和分支
11Streamlit能完成基本交互界面
12Docker / CI能一键运行和自动测试
13MCP把已有工具标准化对外暴露

6. 遇到没有学过的知识时怎么解决

第一步：把问题问具体

不要只问“怎么学习 RAG”，而要问：“我需要让 JobLens 从 20 个 Markdown 文件中找出最相关的 3 个片段，需要学习哪些最少知识？”

第二步：只学习最小概念

实现 RAG 时，第一轮只理解文本切分、Embedding、相似度、Top-K 和如何把检索片段放进 Prompt。不要提前研究大规模向量数据库和 GraphRAG。

第三步：先写最小实验

新知识先放在 experiments/ 中验证。例如学习 SQLite 时，只实现“建表、插入一个岗位、查询、更新状态”。实验成功后再集成到正式代码。

第四步：自己重新实现

  1. 阅读示例。
  2. 关闭示例。
  3. 根据理解重新实现。
  4. 对比差异。
  5. 补充测试。
  6. 用自己的话记录设计原因。

第五步：建立学习日志

问题：为什么模型返回的 JSON 解析失败？ 原因：模型在 JSON 前后增加了解释文字。 解决：使用结构化输出，并由 Pydantic 验证。 验证：新增 3 个异常输出测试。

如果不能解释一段代码为什么存在，它就暂时不应该进入主项目。

7. 推荐调试顺序

  1. 完整阅读错误信息。
  2. 确认错误出现在哪个函数。
  3. 记录该函数的输入。
  4. 在不调用大模型的情况下单独测试工具。
  5. 使用固定的模拟模型结果测试流程。
  6. 最后才检查 Prompt 和模型行为。
Agent 项目出错后不要第一时间修改 Prompt。很多问题实际来自文件路径、JSON、数据库字段或工具参数。

8. 如何合理使用 AI 辅助开发

AI 可以用于解释概念、拆分任务、审查代码、分析报错、设计测试和模拟面试，但不能代替你理解核心逻辑。

每完成一个模块，尝试回答：

  • 这个模块解决什么问题？
  • 输入和输出是什么？
  • 为什么不用更简单的方法？
  • 失败时会发生什么？
  • 如何证明它有效？
  • 如果不用大模型，这部分能否完成？

9. 每周可展示成果

周次可展示成果
第 1 周简历和 JD 结构化解析
第 2 周可调用工具的命令行 Agent
第 3 周岗位保存、查询和比较
第 4 周学习资料 RAG 和来源引用
第 5 周LangGraph 状态机和中断恢复
第 6 周评测集、测试和 Prompt 优化

如果时间有限，完成到第 4 周并做好测试，也已经可以作为第一个实习项目。LangGraph、MCP 和网页界面不是判断项目是否成功的前提。

10. 项目最终完成标准

功能完整

岗位解析、证据匹配、面试准备、学习资料检索和岗位管理都能运行。

结果可信

有引用、有拒绝机制，不编造简历经历或资料来源。

工程可靠

工具可独立测试，错误可追踪，依赖和启动方式清楚。

可以展示

拥有模拟数据、评测结果、README、架构图和演示视频。
